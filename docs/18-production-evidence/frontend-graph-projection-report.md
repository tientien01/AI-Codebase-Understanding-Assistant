## Delivered boundary

- Existing graph GET paths remain compatible and now accept validated active compatibility version, roots, node/edge types, direction, depth, confidence, support and client budget query inputs.
- The server caps requests at 220 nodes, 520 edges and depth 6, applies stable traversal/filter ordering, and never emits an edge whose endpoint is outside the included node set.
- Additive responses bind repository/current integer compatibility version/view and disclose available/included counts, measured coverage, truncation reason, unresolved roots, expansion availability and support provenance.
- A non-active requested compatibility version returns a safe non-retryable `409 GRAPH_INDEX_VERSION_NOT_ACTIVE` conflict. The accepted opaque `index_version_id` surface remains a documented baseline gap rather than being invented from the integer sequence.
- TanStack graph keys include repository, active version, view and normalized projection inputs; API serialization sends deterministic repeated filter parameters and forwards cancellation signals.
- The graph page no longer slices nodes or edges. It renders the complete server projection, labels complete versus limited scope, supports bounded focus/filter/depth/direction/size expansion and exposes every included relation through native keyboard controls.

No database, canonical graph storage, parser/resolver/indexing pipeline, dependency or route-path change was made.
