# Research and Adopted Ideas

Research is informative and cannot authorize implementation.

| Source | Idea to adapt | Project-specific adaptation |
| --- | --- | --- |
| Understand-Anything | Teaching graph, layers, tours, diff overlay | Preserve current pages; add evidence-backed bounded projections and guided flows |
| Aider | Repository map and token budgeting | Versioned repository digest selected by symbol/graph relevance |
| RepoGraph | Definition/reference graph tools | Typed path tools with edge provenance and benchmark comparison |
| Potpie | Context readiness, doctor, CLI/MCP | Capability readiness plus shared application-service adapters |
| OpenHands | Agent instructions, React production patterns | Nested AGENTS, progressive disclosure, Router/Query/testing patterns |

Rejected as defaults: LLM-generated facts, unbounded multi-agent analysis, one giant graph canvas, JSON-only production persistence, and adopting infrastructure without measured triggers.

## Research record rule

Material research gets a repository-specific file recording source URL, reviewed commit/tag and date, license, observed architecture, relevant modules, strengths, weaknesses, candidate adaptation, rejected ideas, benchmark needed, and any proposed ADR/task. Findings without a pinned revision are leads, not reproducible engineering evidence.

An adapted idea enters production only after it maps to a measured project problem, passes the technology adoption process when applicable, and is accepted by an ADR/plan/task. Source code must never be copied without license and compatibility review.
